Flow

主流程

一次上传只读取一次文件，且读取发生在远端冲突确认之后。读取前后各有一次 stat：读取前与任务启动时记录的 baseline 对比，读取后再确认磁盘状态没有变化。

Reader

读取通道解析

Electron 主进程不在 DSM 白名单内，直接 fs.readFile 只能得到密文。 读取器按“优先 → 备用”顺序寻找白名单 Node 或 Python，并通过子进程 stdout 取回明文。

  1. 解析顺序 设置页对应读取器路径 → 环境变量 DSM_NODE_PATH / DSM_PYTHON_PATH → 自动探测。解析成功后缓存结果；版本探测超时 5 秒。
  2. 显式配置不回退 显式配置或环境变量不可执行时抛出 READER_UNAVAILABLE，不会尝试另一个 读取器。helper 缺失、spawn 失败、读取失败和超时同样不会回退。
  3. 自动探测候选 Node：系统 PATH、Windows 的 Program Files / LOCALAPPDATA / APPDATA、macOS 的 Homebrew 与 ~/.nvm/versions/node/*/bin。Python：PATH、Homebrew、 framework、Command Line Tools、pyenv versions 与常见 conda 目录；自动探测排除 Windows Store 别名和 macOS 的 /usr/bin/python3 桩。
  4. 回退记录 只有优先读取器未配置且自动探测完全失败时才尝试另一个；成功后按 INFO 记录实际 读取器、路径、版本和来源。两个都不可用时抛 READER_UNAVAILABLE，消息 同时列出 Node 和 Python。
  5. 用读取测试确认白名单 设置页的「选择文件测试」会分别用主进程和实际读取器读取同一文件，显示大小、SHA-256 与文件头。两者内容不同通常说明读取器已拿到明文；内容相同则说明文件未受控，或该 解释器不在 DSM 白名单中。

Protocol

子进程读取协议

外部读取进程（Node / Python）只做一件事：把文件原始字节写到 stdout。日志和错误全部走 stderr， 避免污染二进制内容；主进程负责超时、超限和退出码处理。

触发 辅助进程行为 主进程结果
正常结束，stdout 非空 写完全部字节，exit 0 Buffer.concat → 读取成功
正常结束，stdout 为空 exit 0 FILE_READ_FAILED「未返回内容」
读取失败 stderr 输出 FILE_READ_FAILED JSON，exit 1 FILE_READ_FAILED，阶段 CHECK
超过大小上限 销毁流，stderr 输出 FILE_TOO_LARGE，exit 2 FILE_TOO_LARGE
超时 120 秒 主进程向子进程发送 SIGKILL FILE_READ_FAILED「读取文件超时」
stdout 累计超限 主进程向子进程发送 SIGKILL FILE_TOO_LARGE
非零退出且 stderr 不是 JSON — FILE_READ_FAILED，错误信息包含退出码

Checks

失败分支与约束

读取不是一次孤立的 fs.readFile：文件状态、大小上限和进程边界都在不同 层重复检查，任何一层失败都会让任务停在读取阶段之前或之后。

三次 stat

选择文件时预检；任务启动时记录 baseline（size + mtimeMs）；读取前与 baseline 对比， 读取后再确认磁盘状态。读取后只比较 size，因为透明加密下明文长度可能与磁盘密文不同。

三处大小上限

inspectLocalFile 预检、辅助进程流式计数、主进程 stdout 累计。 默认上限 50 MiB，任一处超限都会中止读取。

明文不落盘

内容只经过 stdout 管道进入主进程 Buffer，再编码为 Base64 交给 HTTP 请求； 不写临时明文文件，避免被重新加密或残留。

读取失败没有自动恢复

读取相关错误统一标记为 stage = CHECK，任务进入 FAILED。恢复动作表里没有 读取阶段的重试项，需要用户重新发起任务。

显式配置不做回退

用户配置了白名单 Node / Python 却不可执行时，任务直接失败，不会尝试另一个读取器。 这是为了避免掩盖配置错误。

自动探测失败才回退

只有优先读取器未配置且自动探测完全失败时，才尝试另一个读取器；成功后按 INFO 记录 实际路径、版本和来源。两个都不可用时才抛 READER_UNAVAILABLE。
